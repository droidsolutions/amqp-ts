# amqp-ts 4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair CI and release notes on `master`, then build amqp-ts 4.0 on `develop`. 4.0 is ESM-only, runs on amqplib 2 with its promise API, and delegates connection recovery to amqplib while keeping the topology rebuild.

**Architecture:** Phase 1 consists of three small, non-releasing commits on `master`, which the maintainer reviews and pushes. Phase 3 rewrites the connection lifecycle around amqplib's `RecoveringChannelModel`:
- The recovery `setup(model)` hook re-creates one channel per exchange or queue and re-declares the whole topology.
- Each entity re-initializes itself when only its channel dies.
- Before that rewrite, characterization tests pin the 3.x reconnect behaviour against a real broker.

**Tech Stack:** TypeScript 6, Node ≥ 22.13 (ESM, `require(esm)`), amqplib 2.x, mocha + tsx, chai 6, c8 or nyc, semantic-release 25, RabbitMQ 4 (podman locally, GitHub Actions service container in CI).

**Spec:** `docs/superpowers/specs/2026-10-16-amqp-ts-4-design.md`. Read it first. This plan does not repeat its reasoning.

## Global Constraints

- `engines.node`: `">=22.13.0"`. TypeScript `target`: `"ES2024"`. TypeScript major: 6, not 7.
- No top-level `await` anywhere in `src/`.
- Do not use APIs that need Node ≥ 24.
- The package ships ESM only. `exports` contains only `"."` and `"./package.json"`.
- npm 11 for every `npm ci` / `npm install`. Never regenerate the lockfile with npm 10.
- Do not rename `.github/workflows/main.yml`, because OIDC trusted publishing is bound to that name.
- Every commit that breaks the public API carries a `BREAKING CHANGE:` footer.
- The amqplib 1 → 2 bump is its own commit, and its footer links `https://github.com/amqp-node/amqplib/blob/main/CHANGELOG.md`.
- No deprecation shims. Breaking changes are documented in the README's migration section instead.
- The repository is public. No internal company project names, hosts or infrastructure in any file or commit message.
- **Never push.** Phase 1 commits stay local for the maintainer to review and push. Each push to `develop` publishes a prerelease, so ask the maintainer before every push.
- Phase 3 work happens on a local branch `v4` cut from `develop`. Merge into `develop` only at the checkpoints named below.
- Tests need a broker. Locally, run `podman start rabbitmq` (management UI on 15672, `guest`/`guest`).

## Review Focus

1. **Unhandled promise rejections.** When a replaced `initialized` promise is never awaited by the user and recovery gives up or `close()` is called, the process must not crash. Every internally created promise that can reject has a handler attached. → Task 9, test `does not crash on unhandled rejections when recovery gives up`.
2. **Unlistened `error` events.** amqplib channels and the recovering model emit `error`. With no listener, Node throws and kills the process. Every emitter we own has an `error` listener. → Task 8, covered by the channel-failure tests (a 406/404 would crash otherwise) plus test `survives a channel error event without a user listener`.
3. **Entities declared while (re)connecting.** An exchange, queue or binding that is declared during the `setup` hook, or while disconnected, must still be declared on the new connection exactly once. → Task 8, test `declares an entity created while disconnected after the next connect`.
4. **A declaration failure loop.** A queue whose re-declaration fails, for example a `noCreate` queue deleted while the broker was down, must not flap or reconnect forever. → Task 9, test `isolates a failing entity during setup`.
5. **`close()` during recovery.** `close()` while a reconnect is scheduled must resolve, emit `close_connection` once, stop all retries, and leave the process able to exit. → Task 9, test `close during a scheduled reconnect stops recovery`.

**Interfaces:**
- Produces:
  - `src/Connection/RecoveryOptions.ts`:
    `export type RecoveryOptions = Omit<import("amqplib").RecoveryOptions, "setup" | "waitForConnect">;`
  - `Connection`:
    - `constructor(url = "amqp://localhost", socketOptions: <amqplib socket options type> = {}, recovery: RecoveryOptions = {}, loggerFactory?: LoggerFactory)`. It connects with `{ ...socketOptions, recovery: { ...recovery, waitForConnect: false, setup } }`.
    - `initialized: Promise<void>`: resolves after the first connect including the topology. It is replaced by a pending promise on `disconnect` and resolved on the next `connect`. It rejects on `reconnect-failed` or `close()`.
    - `isConnected: boolean`.

    - `close(): Promise<void>`.

    - `@internal _model: ChannelModel | undefined`, `@internal _generation: number`: incremented on each successful connect.
  - Entities (`Exchange`, `Queue`, `Binding`):
    - `@internal _initialize(model: ChannelModel, generation: number): Promise<void>`: creates the channel (exchange/queue), declares, and for a queue with a consumer re-consumes. It settles `initialized` and is a no-op if `generation` was already initialized.
    - `@internal _invalidate(): void`: replaces `initialized` with a fresh pending promise that has a no-op `catch`.
    - `_channel: Channel` (the promise API type).
  - `src/Deferred.ts`: `export class Deferred<T> { promise: Promise<T>; resolve(v: T): void; reject(e: Error): void }`. Its constructor attaches `promise.catch(() => {})`.
  - Event mapping, which keeps the README semantics:
    - first `connect` → `open_connection`
    - later `connect` → `re_established_connection`
    - `disconnect` while not closing → `lost_connection`
    - `reconnect-scheduled` → `trying_connect`
    - `reconnect-failed` → `error_connection(err)`
    - `close()` → `close_connection`
    - The recovering model's `error` is logged at warn.
